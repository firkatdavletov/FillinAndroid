# Запланированные операции

Один пункт нижней навигации «Планы» открывает экран «Запланированные операции» вместо отдельных экранов
расходов и доходов. Переход к обязательствам с главной страницы ведёт на тот же экран.

Список загружается через `GET /api/v1/planned-operations`. Для работы нужен сервер с этим endpoint;
старые списки не используются в качестве запасного источника данных.

- Период: текущий месяц с первого по последнее число (по умолчанию), до конца текущего месяца,
  до конца текущего года либо две даты в календаре.
- Тип: все операции (по умолчанию), расходы или доходы.
- Текущая дата определяется в `Asia/Almaty`. Периоды «До конца месяца» и «До конца года» начинаются сегодня.
  Обе границы произвольного периода включительны;
  допустим один день и прошлые даты для просмотра просроченных планов. Конечная дата — максимум пять лет вперёд.

Период расположен первым и использует общий с историей операций UI-компонент `DatePeriodChip`.
По умолчанию Chip показывает название месяца и стрелку вниз; нажатие сразу открывает календарь.
Для выбранного периода отображаются короткие даты и крестик сброса на текущий месяц; выбранный тип сохраняется.
Быстрые варианты «Текущий месяц», «До конца месяца» и «До конца года» находятся в календаре и применяются сразу.
Произвольные даты применяются кнопкой «Применить»; отмена сохраняет прежний фильтр. Тип и период передаются серверу вместе.
Текущий месяц передаётся как `period=CUSTOM` с явными `dateFrom` и `dateTo`, чтобы включить планы с первого числа.
Смена фильтра отменяет текущий запрос и очищает старый список. Поздний ответ отменённого запроса игнорируется.
Обновление жестом, повтор после ошибки и обновление после изменения плана сохраняют выбранные фильтры.

Расходы и доходы идут одним списком по сроку и UUID, с явными подписями типа. «К оплате» суммирует оставшиеся
обязательства, «К получению» — ожидаемые доходы. Суммы считаются отдельно через `BigDecimal`; план не выдаётся
за фактический баланс. Фильтры доступны при пустой выборке и ошибке. Ошибка обновления сохраняет прежние данные
с кнопкой повтора; потеря доступа очищает список.

«Добавить» предлагает расход или доход и открывает существующую форму. Сохранены редактирование и удаление
правил расходов, закрытие частично оплаченного обязательства, а также создание, редактирование и отмена доходов.
Мутации используют прежние `/api/v1/planned-expenses` и `/api/v1/planned-incomes`, UUID и optimistic version
выбранной строки/правила. После успешной мутации общий список перечитывается с текущими фильтрами.
Редакторы в этом сценарии не загружают старые отдельные списки.

Проверки:

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
ANDROID_SERIAL=emulator-5554 ./gradlew :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=com.firkat.fillin.feature.plannedoperations.ui.PlannedOperationsScreenTest
```

Для UI-прогона нужно выбрать serial отдельного тестового эмулятора через `adb devices`.
Тесты используют синтетические ответы и не обращаются к рабочему API.
