# Запланированные операции

Один пункт нижней навигации «Планы» открывает экран «Запланированные операции» вместо отдельных экранов
расходов и доходов. Переход к обязательствам с главной страницы ведёт на тот же экран.

Список загружается через `GET /api/v1/planned-operations`. Для работы нужен сервер с этим endpoint и полем `totals`;
старые списки не используются в качестве запасного источника данных.

- Период: текущий месяц с первого по последнее число (по умолчанию), до конца текущего месяца,
  до конца текущего года либо две даты в календаре.
- Под периодом — два равных блока «Расходы» и «Доходы» с серверными итогами за весь выбранный период.
  По умолчанию видны оба типа. Выбор блока расширяет его на всю строку, скрывает второй и фильтрует список.
  Крестик справа возвращает оба блока и все типы.
- Текущая дата определяется в `Asia/Almaty`. Периоды «До конца месяца» и «До конца года» начинаются сегодня.
  Обе границы произвольного периода включительны;
  допустим один день и прошлые даты для просмотра просроченных планов. Конечная дата — максимум пять лет вперёд.

Период расположен первым и использует общий с историей операций UI-компонент `DatePeriodChip`.
По умолчанию Chip показывает название месяца и стрелку вниз; нажатие сразу открывает календарь.
Для выбранного периода отображаются короткие даты и крестик сброса на текущий месяц; выбранный тип сохраняется.
Быстрые варианты «Текущий месяц», «До конца месяца» и «До конца года» находятся в календаре и применяются сразу.
Произвольные даты применяются кнопкой «Применить»; отмена сохраняет прежний фильтр. Тип и период передаются серверу вместе.
Текущий месяц передаётся как `period=CUSTOM` с явными `dateFrom` и `dateTo`, чтобы включить планы с первого числа.
Смена фильтра отменяет текущий запрос и очищает старый список. При смене типа итоги периода сохраняются до
нового ответа; при смене дат очищаются. Поздний ответ отменённого запроса не меняет ни список, ни итоги.
Обновление жестом, повтор после ошибки и обновление после изменения плана сохраняют выбранные фильтры.

Расходы и доходы идут одним списком по сроку и UUID, с явными подписями типа. Общий с экраном «Операции»
Compose-компонент `OperationTotalsRow` показывает `totals.expenses` (остатки открытых обязательств к оплате)
и `totals.incomes` (неполученные ожидаемые доходы). Backend считает оба итога до фильтрации списка по `type`
в том же согласованном ответе; Android не суммирует строки и не делает отдельный запрос за итогами.

```json
"totals": {
  "expenses": { "amount": "60.00", "currency": "KZT" },
  "incomes": { "amount": "200.00", "currency": "KZT" }
}
```

Итоги относятся к полному периоду с включительными границами, включая ещё не материализованные расходные
occurrences, которые backend идемпотентно создаёт до конца периода даже при выборе доходов. Из суммы расходов
исключены проведённые оплаты, полностью оплаченные, закрытые и отменённые обязательства; из доходов —
полученные и отменённые планы. При пустом периоде приходят нули. Отсутствующий или некорректный `totals`
считается ошибкой ответа. Плановые суммы не являются фактическим балансом.

Блоки доступны при пустой выборке и ошибке; во время первой загрузки видны индикаторы. Ошибка обновления
сохраняет прежний список и итоги с кнопкой повтора; потеря доступа очищает финансовые данные.

«Добавить» предлагает расход или доход и открывает существующую форму. Сохранены редактирование и удаление
правил расходов, закрытие частично оплаченного обязательства, а также создание, редактирование и отмена доходов.
Мутации используют прежние `/api/v1/planned-expenses` и `/api/v1/planned-incomes`, UUID и optimistic version
выбранной строки/правила. После успешной мутации общий список вместе с итогами перечитывается с текущими фильтрами.
Редакторы в этом сценарии не загружают старые отдельные списки.

Проверки:

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
ANDROID_SERIAL=emulator-5554 ./gradlew --no-configuration-cache :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=com.firkat.fillin.feature.plannedoperations.ui.PlannedOperationsScreenTest
```

Для UI-прогона нужно выбрать serial отдельного тестового эмулятора через `adb devices`.
Тесты используют синтетические ответы и не обращаются к рабочему API.
