# T04 — хранение бюджетных профилей

## Поведение приложения

Существующая Room-база `operations-<hash сервера>.db` регистрируется в новой базе
`budget-profiles.db` как профиль LEGACY. Файл, UUID бюджета и участника, история,
курсор, requestId и payload очередей остаются на месте. Версия схемы бюджета остаётся 4;
применяются прежние миграции 1→2→3→4 без destructive migration.

Новый профиль получает свой файл `budget-<UUID профиля>.db`. Операции, категории,
настройки, роль, курсор, staging и обе очереди принадлежат только этому файлу.
Профиль CLOUD дополнительно хранит Firebase UID и серверный budgetId. Реестр
не допускает два профиля одной пары UID/budgetId и повторное использование файла.
Выбор профиля сохраняется отдельно для локального режима и каждого аккаунта.

Google-вход и выход сохраняют существующий локальный/LEGACY бюджет. Старый бюджет
автоматически не присваивается вошедшему аккаунту: явная серверная привязка — T05.
Для CLOUD выход или смена аккаунта скрывает профиль и открывает локальный выбор;
повторный вход исходного UID восстанавливает его выбор и неизменённые очереди.
Создание и выбор облачных бюджетов в интерфейсе появятся в T05–T08.

## Koin и фоновые задачи

Room, репозитории, use cases, synchronizer, настройки синхронизации и ViewModel
размещены в scope бюджета. Compose получает этот scope и отдельный ViewModelStore,
чтобы после переключения не переиспользовать ViewModel прежнего бюджета.
Firebase Auth, Retrofit и отслеживание сети остаются общими для приложения.

UI и worker удерживают scope до завершения своей работы. Неактивный scope закрывает
базу и фоновые наблюдения после освобождения последнего держателя. Если пользователь
возвращается до завершения старого запроса, переиспользуются тот же Room handle и
mutex synchronizer, чтобы не запускать параллельный обмен одной очереди.

WorkManager получает неизменяемые profileId/UID в inputData. Имя unique work — хеш
этой пары; UID не попадает в имя задачи. Worker проверяет активный профиль и текущий
аккаунт и не подставляет вместо них зависимости нового бюджета. При переключении
отменяются прежний foreground-обмен и его unique work. Уже пришедший ответ обрабатывается
в исходной базе. Очереди не удаляются; возвращение к профилю планирует обмен снова.
Старые задачи без адресации завершаются без обмена; сохранённая очередь обнаруживается
при следующем запуске. LEGACY остаётся без UID до явной привязки в T05.

## Проверка на устройстве

Перед установкой сохранить приватную резервную копию постоянных каталогов приложения
и проверить SQLite integrity. APK устанавливать только поверх существующего приложения:

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w \
  -e class com.firkat.fillin.feature.budgetprofile.BudgetProfilesDeviceTest,com.firkat.fillin.feature.budgetprofile.BudgetProfileScopeUiTest,com.firkat.fillin.OfflineDependenciesTest \
  com.firkat.fillin.test/com.firkat.fillin.FillinTestRunner
```

`connectedDebugAndroidTest` на личном устройстве не использовать: этот Gradle task
может удалить приложение с его данными. Тесты T04 используют собственные файлы баз,
синтетическую авторизацию и API. У тестового Application выключен автоматический обмен.

Ручная приёмка установленной сборки:

1. Проверить прежний баланс и историю; в авиарежиме добавить локальную операцию.
2. Включить сеть, открыть «Облако», войти в Google, выйти и войти снова.
3. Перезапустить приложение: бюджет и добавленная операция должны остаться прежними.

Проверка двух профилей и UID выполняется instrumentation-тестами: пользовательского
переключателя бюджетов в T04 ещё нет. Реальные Firebase-токены и серверные контракты
при этой задаче не меняются.

## Результаты (2026-10-21)

- Debug APK и instrumentation APK собраны, 181 unit-тест прошёл.
- Сборка установлена на Pixel 10 Pro XL поверх существующего приложения.
- Полный instrumentation-прогон: `OK (78 tests)`, из них 76 успешных и 2 live Firebase
  проверки пропущены без opt-in. Включены 8 новых device-тестов T04: регистрация старой
  базы, две базы и обе очереди, UID/выход/восстановление выбора, отложенный ответ,
  возвращение к занятому scope, адресация workers и смена ViewModel/баланса в Compose.
- После установки и полного прогона история, суммы, UUID, курсор и обе очереди
  существующего бюджета совпали с приватной резервной копией. В `operation_sync_state`
  изменилось только служебное поле `lastSyncedAt`. SQLite integrity check успешен.
  Реестр ссылается на прежнее имя файла; UID ему не назначен.
- Первый Compose-прогон не получил UI при заблокированном Pixel. После разблокировки
  пользователем прошёл весь набор, включая этот тест.
- Вход/выход для нескольких профилей проверены с синтетическими аккаунтами. Ручная
  проверка текущего бюджета с настоящим Google-входом остаётся приёмкой пользователя.
