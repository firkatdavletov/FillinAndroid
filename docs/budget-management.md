# Переименование и удаление бюджетов

В профиле карандаш и корзина на карточке открывают bottom sheet. Облачным бюджетом
управляет OWNER; локальным — пользователь устройства. Название после trim содержит
1–80 символов без управляющих символов. Для удаления требуется повторить название
с учётом регистра. Подтверждение необратимо, включая несинхронизированные операции.

Room-реестр версии 7 хранит очередь budget_management отдельно от финансовых баз.
Переименование отображается сразу поверх серверного каталога. Удаляемый бюджет скрыт
и недоступен для выбора и финансовой синхронизации. После удаления выбранного бюджета
сохраняется явное требование выбора; перезапуск не выбирает запасной бюджет автоматически.

Account-level WorkManager-задача отправляет очередь независимо от активного бюджета.
UID проверяется перед запросом и после ответа. Временные ошибки сохраняют requestId
и payload для повтора; другой аккаунт не отправляет исходную очередь. Незавершённый
импорт разрешается прежним запросом до управления бюджетом. Финансовые команды ради
удаления не отправляются. После подтверждения сервера освобождаются Room/runtime,
удаляется файл и его служебные записи. Незавершённая очистка повторяется после сбоя.

Статусы удаления видны в профиле и на экране выбора. Изменение прав проверяется
успешным чтением каталога; недоступный бюджет очищается, доступный возвращается с
серверными данными и сообщением об отказе. Один сетевой сбой не означает удаление.
Каталог обновляется при foreground, восстановлении сети (ограничение WorkManager),
входе и завершении финансовой синхронизации. Офлайн-клиент узнаёт об удалении после
следующего успешного обмена. Мгновенные push-уведомления не используются.

## API и выпуск

- PATCH /api/v4/budgets/{budgetId}: {requestId, name}, ответ — описание бюджета.
- DELETE /api/v4/budgets/{budgetId}?requestId=UUID: ответ 204 без тела.
- Firebase Bearer token, OWNER, Cache-Control: no-store.
- Повтор запроса не выполняет запись заново. Другой payload с тем же requestId: 409.
- Последнее принятое сервером переименование определяет актуальное название.

Требуется FinanceConsultante с V31. Сначала выпустить backend, затем Android.
Production-развёртывание выполняется отдельно. Начальный баланс и дата не редактируются.

Проверки: :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest;
прямой instrumentation-прогон BudgetManagementDeviceTest, BudgetManagementUiTest,
BudgetProfileMigrationTest и ProfileBudgetsRepositoryTest на эмуляторе.
Личные устройства не очищать; connectedDebugAndroidTest для них не использовать.
