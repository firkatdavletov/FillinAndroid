# T06 — первый облачный бюджет

## Доступно в сборке

В «Облако» после Google-входа аккаунт без бюджетов получает действие «Создать облачный бюджет».
На первом запуске без готового бюджета: «Войти через Google» сразу открывает Google-вход.
После входа аккаунт без бюджетов получает форму создания, аккаунт с бюджетами — список для выбора.
Незавершённое создание восстанавливается перед открытием новой формы. Кнопка
«Продолжить без авторизации» открывает настройку локального бюджета без Google-входа.
Возврат к приветствию сохраняет Google-сессию; повторное нажатие кнопки входа продолжает настройку.
Отдельной регистрации нет: Firebase создаёт аккаунт при первом Google-входе.

Форма принимает название до 80 символов, начальный баланс в KZT и дату начала учёта
`ГГГГ-ММ-ДД`, не позже текущей даты Asia/Almaty. Нулевой и отрицательный начальный баланс
разрешены; точность — до двух знаков, без округления. Запятая в Android преобразуется в точку.

Успешное создание загружает полный срез в отдельную Room-базу и выбирает новый облачный профиль.
Прежний локальный бюджет сохраняется. Его [перенос T07](firebase-local-budget-upload.md) доступен отдельным действием; создание дополнительных бюджетов
из интерфейса и переключение доступны в [T08](firebase-multiple-budgets.md). Сервер уже допускает несколько бюджетов одного UID.

## Повторы и восстановление

Перед HTTP Android сохраняет UID, requestId и неизменную форму в `pending_budget_creation`.
Room-реестр профилей обновляется с версии 1 на 2 без пересоздания существующих профилей.
Токен в этой таблице не хранится. Каждый запрос получает Firebase ID token из SDK;
первый 401 вызывает одно принудительное обновление и повтор того же payload.

При потере ответа, отмене coroutine или ошибке загрузки запрос остаётся привязан к исходному UID.
После перезапуска и повторного входа видна заполненная неизменяемая форма и «Продолжить создание».
Новый requestId для неё не создаётся. Запрос удаляется после загрузки и выбора профиля;
окончательный HTTP 400 позволяет исправить форму. Для другого аккаунта запрос скрыт.

## Сервер

`POST /api/v4/budgets`, `Authorization: Bearer <Firebase ID token>`:

```json
{
  "requestId": "11111111-1111-4111-8111-111111111111",
  "name": "Тестовый бюджет",
  "openingBalance": "1234.50",
  "accountingStartedOn": "2026-10-20",
  "currency": "KZT"
}
```

Ответ 200: `{id, name, memberId, role: "OWNER"}`. Проверенный UID берётся из токена.
Сервер транзакционно создаёт household, OWNER без Telegram ID, счёт, четыре базовые категории,
Firebase-членство и receipt. Начальный баланс не записывается как доход.

V25 вводит `firebase_budget_creation` с PK `(firebase_uid, request_id)` и FK на членство.
Транзакционная блокировка этого ключа сериализует конкурентные повторы. Тот же запрос возвращает
прежний бюджет; изменённый payload — 409 `idempotency_conflict`. Любая ошибка до commit
откатывает все начальные данные. У другого UID тот же requestId имеет отдельную область.

Прежнее статическое создание перенесено на `POST /api/v4/legacy/budgets`, чтобы основной
путь принимал Firebase. Прежние чтение/обмен не изменены; их удаление остаётся T12.
Необходимо обновить сервер FinanceConsultante с V25 перед живой проверкой Android.
Адрес Firebase API в обычной сборке остаётся настроенным Railway URL. Развёртывание отдельно.

## Проверка на устройстве

1. На обновлённом тестовом сервере войти вторым Google-аккаунтом без бюджетов.
2. «Облако» → «Создать облачный бюджет» → название, баланс `1234,50`, дата сегодня → создать.
3. Добавить расход `12,34`, дождаться синхронизации: остаток должен быть `1222,16`.
4. Перезапустить приложение: бюджет и операция остаются.
5. На другом устройстве или эмуляторе войти тем же аккаунтом, выбрать бюджет: баланс и операция совпадают.
6. Прервать сеть при создании, затем нажать «Продолжить создание»: в списке должен остаться один бюджет.

Обычные тесты используют синтетические данные и заглушки Firebase; настоящие Google-аккаунты
и второй физический клиент требуют отдельной ручной приёмки после обновления тестового сервера.
Установка на личный Pixel выполняется через `adb install -r`, без удаления приложения и очистки данных.

- После последнего уточнения кнопки «Войти в облако» обе проверки первого запуска повторены успешно.
- Проверены создание OWNER, ввод и валидация формы, загрузка в отдельную базу, расход и синхронизация,
  повторное открытие Room/Koin, независимый второй клиент с другим файлом, потерянный ответ,
  ошибка загрузки, повтор с тем же requestId, смена аккаунта и миграция реестра 1→2.
- Сервер `test check bootJar`: успешно, 315 unit и 276 integration-тестов без пропусков;
  реальные PostgreSQL 17.11/Testcontainers, ktlint, Detekt, JaCoCo.
