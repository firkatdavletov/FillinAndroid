# Удаление профиля Android

Кнопка находится внизу страницы профиля. Подтверждение требует ввода `УДАЛИТЬ`.
Удаление доступно также для неподтверждённого email. При `recent_login_required`
пользователь подтверждает вход тем же аккаунтом через Firebase SDK.

Операция сохраняется до HTTP в зашифрованном атомарном файле `noBackupFilesDir`.
Ключ AES-GCM хранится в Android Keystore. Один секрет используется для всех повторов.
Облачные действия UID блокируются до отправки. После перезапуска сначала выполняется GET
статуса, без Firebase-токена. Ответ DELETE `202` означает принятие, а не завершение Firebase.
После принятия сохраняется маркер, выполняются выход и повторяемая локальная очистка.
При `COMPLETED` и успешной очистке секрет удаляется; запрет обмена старого UID сохраняется.
Пароли, ID-токены и секрет операции не пишутся в логи, аналитику и URL.

Очистка удаляет облачные базы UID, включая архивы и очереди, каталог и незавершённые
создания/загрузки. Перед удалением закрываются бюджетные scopes и все UI/worker leases.
Автономные LOCAL/LEGACY-бюджеты и данные других аккаунтов сохраняются.
Пропавший общий бюджет очищается только после успешного списка: сравниваются предыдущий
каталог и новый результат. Ещё не отправленные локальные загрузки не считаются удалёнными.

Проверка статуса выполняется при запуске и каждые 10 секунд при открытом профиле;
после ошибок задержка увеличивается до 60 секунд. После неопределённого результата
отмена и автоматическое возобновление обмена не предлагаются. `409` с неизвестной исходной
операцией показывается как проблема: самостоятельно заменить секрет нельзя.

Для выпуска нужен сервер с API удаления и миграцией V30. Instrumentation отключает
автоматическое восстановление сетевых операций; тесты используют синтетические аккаунты
и локальные серверы. Реальное удаление аккаунта в тестах не выполняется.
