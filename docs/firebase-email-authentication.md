# Вход по email/password

Реализованы email-вход, регистрация, подтверждение, восстановление и привязка Google ↔ пароль. Существующие Google-вход и локальные бюджеты сохраняются. Все пароли и письма обслуживаются Firebase SDK; сервер получает только Firebase ID token. Клиент не хранит пароль или refresh token в БД, SavedStateHandle и навигации.

## Подготовка Firebase Console (выполняет владелец проекта)

1. Открыть проект **fillin-77e97**, Authentication → Sign-in method. Включить **Email/Password**, сохранить Google включённым. Email link не включать для этого сценария.
2. Authentication → Settings → Password policy: режим Require, минимум **12 символов**, без обязательных требований к регистру, цифрам и спецсимволам. Не включать принудительное обновление паролей существующих пользователей. Приложение не ограничивает длину пароля при входе.
3. Settings → User actions: проверить включённую **email enumeration protection**. Приложение не использует предварительный поиск способов входа по адресу.
4. Templates: настроить русские письма **Email address verification** и **Password reset**, имя приложения и адрес поддержки. Использовать стандартный Firebase action handler в браузере; собственные deep links не нужны. SDK задаёт язык `ru` перед отправкой.
5. Сверить `project_info.project_id` локального `app/google-services.json` с project ID Firebase Admin на сервере: оба должны быть `fillin-77e97`. Проверить настройки Google OAuth и сертификаты по [настройке Firebase](firebase-setup.md). Административные ключи в Android не добавлять.
6. Сначала развернуть совместимый сервер: оба провайдера, JSON-код `email_not_verified`, nullable displayName, endpoints `/api/v4/auth/firebase` и `/api/v4/budgets`. Затем выпускать Android после ручной приёмки ниже.

Эти инструкции не меняют Console или сервер автоматически.

## Поведение

Регистрация создаёт аккаунт, затем отправляет подтверждение. Ошибка отправки оставляет созданный аккаунт и сессию: повторная кнопка отправляет только письмо. После успешной отправки действует пауза 60 секунд; ограничения Firebase обрабатываются отдельно. Пауза принадлежит Activity ViewModel; после завершения процесса ограничения Firebase продолжают действовать.

Подтверждение проверяется на экране при возврате из браузера и вручную: reload → новый currentUser → принудительное обновление токена → публикация готовой сессии → серверный профиль → каталог бюджетов. Ошибка обновления токена не открывает доступ. До подтверждения доступен локальный режим; вернуться к подтверждению можно из профиля. Локальные базы и очереди не удаляются и автоматически аккаунту не присваиваются.

В профиле доступен раздел «Способы входа». Добавление пароля использует текущий адрес аккаунта; привязка Google требует совпадения email. Проверка адреса Google в клиентском токене нужна для выбора аккаунта; достоверность credential проверяет Firebase, доступ к бюджетам — сервер. Сопоставление email никогда не заменяет UID. При необходимости свежего входа запрашиваются существующие credentials, затем привязка повторяется один раз. Конфликт с другим UID останавливает привязку. Отвязка, слияние аккаунтов, изменение email и удаление аккаунта не реализованы.

Восстановление открывает стандартную страницу Firebase. Ответ в приложении нейтральный: «Если для адреса доступно восстановление, вы получите письмо». После смены пароля нужно вернуться ко входу и использовать новый пароль.

`401` обновляет ID token и повторяет исходный запрос один раз. `email_not_verified` переводит сессию к подтверждению и останавливает облачные операции без удаления очереди. `access_denied` означает отсутствие прав. Сеть и временные ошибки сервера сохраняют сессию и данные. Новый аккаунт получает `200 []` и использует существующий явный сценарий создания/импорта бюджета.

## Автоматическая проверка

```
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest
```

Compose-тесты `EmailAuthUiTest` и регрессия `AppNavigationUiTest` используют fake repository и отдельный эмулятор. Не применять `connectedDebugAndroidTest` на основной установке: в истории проекта такой запуск удалял приложение и данные. Устанавливать APK через `adb -s emulator-5554 install -r` и запускать instrumentation с явным serial. Реальные письма и рабочие финансовые данные автоматические тесты не используют.

## Ручная приёмка владельцем

Использовать тестовые адреса и бюджет, не основной финансовый аккаунт.

1. Зарегистрировать новый адрес. Проверить неправильный email, короткий пароль, несовпадающий повтор и корректную регистрацию. Убедиться, что имя не требуется.
2. До подтверждения проверить отсутствие серверного профиля/членства, сохранность локального бюджета, переход в локальный режим и перезапуск. В профиле доступно подтверждение.
3. Проверить доставку письма, папку «Спам», русскую локализацию и стандартную страницу Firebase. Нажать «Я подтвердил email» до открытия письма: доступ не открывается. Повторная отправка доступна через минуту.
4. Подтвердить адрес в браузере, вернуться в приложение. Проверить успешные auth → budgets, выбор/создание бюджета и повторный вход.
5. Отключить сеть на отправке письма после создания аккаунта. Вернуть сеть и повторить отправку: повторной регистрации нет, бюджет сохранён.
6. Google → пароль: войти Google, открыть «Способы входа», добавить пароль, выйти и войти по email. Сверить UID, серверный UUID, выбранный бюджет и историю.
7. Пароль → Google: войти по паролю, привязать Google с тем же адресом, выйти и войти Google. Сверить те же идентификаторы и данные. Выбор другого адреса должен быть отклонён. Проверить требование свежего входа на старой сессии.
8. Восстановить пароль, получить письмо, поменять пароль в браузере. Войти новым паролем; старый пароль не подходит. Неизвестный адрес получает нейтральное сообщение.
9. Проверить ошибку сети и ограничения Firebase без повторяющейся автоматической отправки писем; ошибки 401/403/503 — на тестовом сервере. Очередь несинхронизированных операций должна сохраниться.

Источники: [парольная авторизация](https://firebase.google.com/docs/auth/android/password-auth), [управление пользователями](https://firebase.google.com/docs/auth/android/manage-users), [привязка](https://firebase.google.com/docs/auth/android/account-linking).
