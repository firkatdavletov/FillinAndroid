# T08 — несколько облачных бюджетов

## Доступно в приложении

В «Облако» показаны бюджеты текущего Google-аккаунта с названиями и ролями
«Владелец» / «Участник». Выбранный бюджет отмечен. Кнопка «Создать ещё бюджет»
открывает форму названия, начального баланса и даты. После создания выбирается новый
бюджет. Прежний бюджет и его операции остаются отдельными.

Названия, memberId и роли из проверенного ответа сервера сохраняются отдельно для
каждого Firebase UID. При недоступности сервера остаётся сохранённый список. Бюджет,
который уже полностью загружен на устройство, можно выбрать без сетевого запроса.
Первое открытие другого бюджета требует интернета и полной начальной загрузки;
ошибка загрузки не переключает приложение на частичные данные.

После обновления с T07 нужно один раз получить список онлайн, чтобы сохранить
названия и роли ранее подключённых бюджетов. Выбранный ранее профиль и его данные
доступны и до этого. Авторизация Firebase сохраняется прежним способом; новый
Google-вход без интернета не выполняется.

## Данные и синхронизация

Каждая пара UID/budgetId получает собственный профиль и Room-файл. При выборе
восстанавливаются операции, начальный баланс, курсор, роль и очередь этого файла.
Выбор хранится отдельно для каждого аккаунта и восстанавливается после перезапуска.
Переключение не изменяет requestId, payload и содержимое неактивных очередей.

ActiveBudgetManager меняет Koin scope и ViewModelStore, отменяет прежний foreground-
обмен и WorkManager-задачу. Worker получает неизменяемые profileId/UID и перед работой
проверяет, что они ещё выбраны и принадлежат текущему аккаунту. Автоматический обмен
планируется только для выбранного профиля. Когда пользователь возвращается к бюджету,
его очередь снова отправляется. Отключённая сеть сохраняет очередь на устройстве.
Уже отправленный запрос может завершиться в прежнем бюджете; повтор использует тот
же requestId и не меняет деньги второй раз.

Room-реестр мигрирует 3→4 добавлением таблицы cloud_budget_catalog с ключом
(firebaseUid, budgetId). Миграции 1→2→3→4 зарегистрированы без destructive migration.
Профили, выбор, незавершённое создание T06 и перенос T07 сохраняются. Версия схемы
отдельных финансовых баз остаётся 4. ID token в каталоге не хранится.

Повтор создания дополнительного бюджета после потери ответа использует сохранённый
requestId. Пока запрос не завершён, форма не позволяет заменить его новым бюджетом.
Выход скрывает список и облачные профили; возвращение исходного UID восстанавливает их.

## Сервер

Используются существующие контракты T05–T07: GET/POST /api/v4/budgets и обмен
/api/v4/budgets/{budgetId}/sync/…. Изменения серверного кода или Flyway для T08
не нужны. Сервер уже допускает несколько бюджетов одного UID. PRIMARY KEY
(firebase_uid, household_id) в firebase_budget_access и уникальный member_id
не допускают дублирования членства. Каждый запрос проверяет активного участника
по проверенному UID и budgetId; роль из локального каталога не даёт серверных прав.

Семейные приглашения и управление участниками остаются в T09–T10. Сохранённый
каталог позволяет читать загруженные данные офлайн; актуальные права проверяет сервер
при следующем обмене. Production-развёртывание отдельно.

## Проверка на устройстве

1. Войти через Google, открыть «Облако», выбрать или создать бюджет «Личный»
   с начальным балансом 100,00. Добавить расход 11,25: остаток 88,75.
2. Нажать «Создать ещё бюджет», создать «Семейный» с балансом 900,00.
   Добавить расход 22,50: остаток 877,50. «Личный» остаётся в списке.
3. Отключить интернет, добавить ещё расход 1,00 в «Семейный», переключиться
   в «Личный» и обратно. Балансы должны быть 88,75 и 876,50 соответственно;
   неотправленный расход принадлежит только «Семейному».
4. Перезапустить приложение офлайн: выбран тот же бюджет, расход и очередь сохранены.
5. Включить сеть, синхронизировать выбранный бюджет, затем выбрать другой.
   На втором устройстве войти тем же аккаунтом и проверить оба бюджета отдельно.
6. Выйти и войти другим аккаунтом: прежний список скрыт. Вернуться исходным:
   восстанавливается его выбор и данные.

Автоматические тесты используют отдельные Room/Koin-хранилища, синтетическую
авторизацию и API. Это не заменяет ручную приёмку с реальным Google-аккаунтом,
тестовым сервером и вторым устройством.

## Проверки реализации

Команды Android:

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest
adb -s DEVICE install -r app/build/outputs/apk/debug/app-debug.apk
adb -s DEVICE install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s DEVICE shell am instrument -w com.firkat.fillin.debug.test/com.firkat.fillin.FillinTestRunner
```

Не использовать connectedDebugAndroidTest на личном устройстве: он может удалить
приложение и данные. До установки сохранить приватную резервную копию и проверить
SQLite integrity; после тестов сверить исходные финансовые таблицы и очереди.
