# PNG-иконки категорий

Код иконки — произвольная непустая строка. Android хранит его без нормализации и проверки
по каталогу: неизвестные коды проходят чтение, локальные команды, перезапуск и синхронизацию.
Редактирование названия не изменяет код. Новый код записывается только при явном выборе иконки.

Каталог `CategoryIcons` находится в UI-слое и содержит 23 PNG с русскими подписями.
Коды совпадают с именами `ic_category_*.png` без префикса, в верхнем регистре.
`CategoryIconImage` использует общий объект `FillinIcons`, сохраняет исходные цвета PNG
и физический размер изображения при увеличении шрифта. Android выбирает ресурс плотности
от mdpi (24×24 px) до xxxhdpi (96×96 px).

Для совместимости отображения поддерживаются соответствия:

| Прежний код | PNG-код |
| --- | --- |
| FOOD | GROCERIES |
| TRANSPORT | CAR |
| CLOTHES | CLOTHING |
| EDUCATION | BOOKS_EDUCATION |
| INCOME | SALARY |

Коды HOME, HEALTH, ENTERTAINMENT, SPORT и PETS совпадают с PNG-кодами напрямую.
Для TRAVEL, OTHER, пустого или неизвестного кода отображается `ic_category_household_goods`.
Запасное изображение не означает выбор HOUSEHOLD_GOODS: исходный код сохраняется, а в
редакторе показывается подпись «Другая иконка». Нормализация применяется только при
поиске известного изображения в UI и не записывается обратно в данные.

PNG используются в списке и редакторе категорий, выборе иконки, карточках категорий операций
и формах плановых доходов/расходов. Текстовые описания конфликтов содержат название без emoji.
Совместимые поля `emoji`/`iconEmoji` и схема Room сохраняются; UI их не использует.

Сервер FinanceConsultante должен включать V28, снимающую ограничение списка `icon_code`,
и хранить/возвращать исходный код как строку. Структура JSON не меняется; устаревшие emoji-поля
содержат `📦`. После этого новые PNG добавляются только в приложение без обновления сервера.
Сначала выпускается сервер, затем Android; развёртывание выполняется отдельно.

Проверки: `testDebugUnitTest`, `lintDebug`, `assembleDebug`; инструментальные
`CategoryIconsUiTest` и `BudgetOfflinePersistenceTest#opaqueIconSurvivesLocalSaveRestartRenameAndSync`.
Compose-проверки охватывают 23 PNG в светлой/тёмной теме при обычном и двойном размере шрифта,
запасное изображение, явный выбор иконки, прежний код и недоступность во время сохранения.
Room-проверка использует синтетический сервер и сохраняет неизвестный код через перезапуск,
переименование и синхронизацию.
