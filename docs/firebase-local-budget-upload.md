# T07 — подключение локального бюджета к аккаунту

## Доступно в Android

В «Облако» локальный бюджет получает действие «Подключить к аккаунту» и поле названия.
Если вход ещё не выполнен, кнопка открывает существующий Google-вход. После входа нужно
вернуться в «Облако» и подтвердить подключение нужного локального бюджета. Доступные
локальные бюджеты остаются в этом разделе даже при восстановлении другого облачного профиля.

Если у аккаунта уже есть бюджеты, локальный добавляется ещё одним. Данные не объединяются.
После подключения используются прежние профиль, файл Room, householdId/memberId, UUID категорий,
операций и сохранённая очередь v4. Начальный баланс остаётся начальным балансом, не доходом.
Интерфейс переключения нескольких облачных бюджетов относится к T08.

## Восстановление и выход

Реестр профилей Room мигрирует 2→3 без пересоздания данных. В одной транзакции сохраняются
исходный bootstrap, название и UID, а существующий профиль становится CLOUD того же аккаунта.
Ни ID token, ни Google credentials в этой записи не сохраняются. Исходный bootstrap не меняется;
его requestId был создан при настройке локального бюджета.

Привязка фиксируется **до HTTP**. После выхода такой бюджет скрыт, даже если ответ импорта
ещё не получен. Исходный UID восстанавливает прежний файл и очередь. Другой UID не может
продолжить этот перенос. Смена аккаунта во время запроса не даёт отправить команды от его имени.

Затем включается обмен и ставится WorkManager-задача с profileId/UID. Все сетевые операции идут
через новый CLOUD scope. Если процесс остановился между записью профиля и включением обмена,
«Продолжить подключение» включает его повторно. Кнопка также позволяет продолжить после обрыва
сети; повторное название не заменяет уже сохранённое.

Обычный синхронизатор сначала подтверждает тот же bootstrap через Firebase, затем отправляет
прежние команды. Потеря ответа импорта или финансовой команды сохраняет requestId/payload.
Данные остаются доступными офлайн в исходном аккаунте. Отключение синхронизации сохраняет очередь.

Перенос поддерживает локальные бюджеты v4, которые ещё не обменивались с сервером и имеют
сохранённый bootstrap. Прежде синхронизированный бюджет подключается через список T05;
старые очереди v1–v3 не преобразуются и не удаляются.

## Серверный контракт

Нужен сервер FinanceConsultante с изменениями T07; новая Flyway-миграция после V25 не требуется.
`POST /api/v4/budgets/import`, Firebase ID token в `Authorization: Bearer …`:

```json
{
  "name": "Бюджет с устройства",
  "budget": {
    "requestId": "11111111-1111-4111-8111-111111111111",
    "householdId": "22222222-2222-4222-8222-222222222222",
    "memberId": "33333333-3333-4333-8333-333333333333",
    "openingBalance": "100.00",
    "accountingStartedOn": "2026-10-20",
    "categories": [
      {"id":"44444444-4444-4444-8444-444444444444","name":"Продукты","kind":"EXPENSE","icon":"FOOD","dictionaryKey":"GROCERIES"},
      {"id":"55555555-5555-4555-8555-555555555555","name":"Здоровье","kind":"EXPENSE","icon":"HEALTH","dictionaryKey":"HEALTH"},
      {"id":"66666666-6666-4666-8666-666666666666","name":"Зарплата","kind":"INCOME","icon":"INCOME","dictionaryKey":"SALARY"},
      {"id":"77777777-7777-4777-8777-777777777777","name":"Другое","kind":"EXPENSE","icon":"OTHER","dictionaryKey":"OTHER"}
    ]
  }
}
```

`categories` содержит объекты `{id,name,kind,icon,dictionaryKey}` для
GROCERIES/HEALTH/SALARY/OTHER, с исходными UUID, названиями, типами и иконками.
Ответ 200 `{id,name,memberId,role:"OWNER"}` содержит исходные идентификаторы.
Остальная история отправляется неизменной очередью `/api/v4/budgets/{budgetId}/sync/commands`.

Сервер проверяет Firebase до DB-транзакции. Household, OWNER, счёт, категории, членство и receipt
фиксируются атомарно. Receipt V25 по UID/requestId отличает импорт от создания T06. Повтор исходного
запроса возвращает тот же бюджет; изменённый payload даёт `idempotency_conflict`. Занятые исходные
UUID дают `budget_identity_conflict`, не присваивая чужой бюджет. Транзакционные блокировки
исходных идентификаторов защищают конкурентные попытки, в том числе от двух UID.

## Ручная приёмка

1. Без аккаунта и интернета создать локальный бюджет с балансом `100,00`, добавить расходы
   `12,34` и `7,66`. Перезапустить приложение: остаток `80,00`, история сохраняется.
2. Включить интернет, открыть «Облако» → «Подключить к аккаунту», войти через Google.
3. В «Облако» указать название и подключить этот локальный бюджет. Проверить остаток и историю.
4. На другом устройстве/эмуляторе войти тем же аккаунтом, выбрать добавленный бюджет:
   должны совпасть остаток и UUID операций. Прежние облачные бюджеты остаются отдельными.
5. Прервать связь во время подключения или обмена, перезапустить приложение и продолжить:
   повтор не создаёт второй бюджет и не меняет деньги повторно.
6. Выйти и войти другим аккаунтом: перенесённый бюджет скрыт. Вернуться исходным:
   доступны прежние данные и неотправленная очередь.

Production-развёртывание выполняется отдельно. Автоматические проверки используют синтетические
данные и Firebase/API-заглушки; реальная приёмка Google на обновлённом тестовом сервере отдельно.
