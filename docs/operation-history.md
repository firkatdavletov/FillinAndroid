# История операций

Экран «Операции» использует `GET /api/v1/operations` и показывает расходы и доходы.
При первом открытии показаны все типы операций за период с первого числа текущего месяца
до сегодняшней даты включительно. Текущая дата определяется в `Asia/Almaty`; например,
17 октября 2026 года начальный период — 1 — 17 октября.

- Период стоит первым и отображается как Chip: по умолчанию — название текущего месяца и стрелка вниз.
  Нажатие открывает календарь с начальной и конечной датами, обе включительно; диапазон применяется
  кнопкой «Применить». Для произвольного периода Chip показывает короткие даты (например, `16 Снт - 25 Окт`)
  и крестик. Если даты относятся к разным годам, показаны также годы. Нажатие на крестик возвращает
  период с начала текущего месяца до сегодня, сохраняя выбранный тип операции.
- Под периодом находятся два равных блока: «Расходы» и «Доходы» с итогами за весь период в KZT.
  Нажатие на блок выбирает его тип: блок занимает всю строку, второй скрывается, справа появляется крестик.
  Крестик возвращает два блока и список всех типов. Отдельных фильтров типа и категории больше нет.

Список и итоги приходят одним ответом `GET /api/v1/operations`:

```json
{
  "items": [],
  "nextCursor": null,
  "totals": {
    "expenses": { "amount": "15000.12", "currency": "KZT" },
    "incomes": { "amount": "1000000.34", "currency": "KZT" }
  }
}
```

`totals` считается сервером за весь период `dateFrom`/`dateTo`, независимо от `type`, `categoryId`,
`cursor` и `limit`. Android не загружает остальные страницы ради сумм и не складывает итоги страниц.
Пустая отфильтрованная страница также может иметь ненулевые итоги. Сервер учитывает только POSTED-записи:
возвраты уменьшают расходы по дате возврата, отменённые операции исключены. Чистые расходы могут быть
отрицательными; нулевой итог передаётся сервером явно. Отсутствующее или некорректное поле `totals`
считается ошибкой ответа, а не нулевой суммой.

При смене типа итоги сохраняются до нового ответа, при смене периода сбрасываются, чтобы не показывать
суммы за старые даты. Во время первой загрузки показаны индикаторы; при ошибке доступен общий повтор
загрузки истории. Обновление жестом сохраняет прежние данные до успеха. Исправление суммы и возврат
перезагружают список вместе с итогами.

Фильтры передаются серверу как `type`, `dateFrom`, `dateTo`. Все типы означают отсутствие `type`;
категория не ограничивается. Смена фильтра отменяет текущую загрузку, сбрасывает курсор и загружает
первую страницу; пагинация, обновление жестом и повтор после ошибки используют те же фильтры.

Доходы и расходы имеют разные знаки и отдельные суммы дня. Отменённые записи остаются видимыми,
но не входят в суммы. Исправление и возврат доступны только для расходов через прежние `/api/v1/purchases/{id}`.
Для работы приложения backend должен быть развёрнут с полем `totals` в ответе истории операций.

Проверки:

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
ANDROID_SERIAL=emulator-5554 ./gradlew :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=com.firkat.fillin.feature.operationhistory.ui.OperationHistoryScreenTest
```

Перед UI-прогоном выберите serial нужного тестового эмулятора через `adb devices`; `ANDROID_SERIAL`
ограничивает запуск этим устройством.

Unit- и UI-тесты используют синтетические данные и не обращаются к рабочему API.
